# Установка Unica для Cursor: инструкция для ИИ-агента

Этот файл написан для ИИ-агента, которого пользователь попросил установить
Unica для Cursor. Выполняй шаги по порядку. Если шаг не удался, остановись и
дословно покажи пользователю текст ошибки. Не обходи ошибки самостоятельно.

Человеку удобнее читать [README](../README.md) и [подробное руководство](usage.md).

## Что ты делаешь

1. Клонируешь репозиторий адаптера в постоянную папку.
2. Ставишь Unica на компьютер командой `install`.
3. Включаешь Unica в проекте пользователя командой `enable`.
4. Просишь пользователя перезагрузить окно Cursor.

Ты не меняешь исходники 1С, не настраиваешь подключение к информационной базе
и не запрашиваешь пароли.

## 0. Проверь условия

- ОС — Windows x64. На других системах скрипт не работает: сообщи об этом
  пользователю и остановись.
- `git --version` выполняется. Если нет, попроси пользователя установить
  [Git for Windows](https://git-scm.com/download/win) и остановись.
- Определи папку проекта 1С. По умолчанию это первая папка открытого workspace.
  Если в workspace несколько папок или проект неочевиден, спроси пользователя.
  Unica работает только с первой папкой workspace.

## 1. Клонируй репозиторий

Папка установки: `%USERPROFILE%\unica-cursor`. Она должна остаться на диске
после установки: команды `enable`, `update` и другие берут из неё шаблоны.

- Если папки нет:
  `git clone https://github.com/VictorMurashkin/unica-cursor.git "%USERPROFILE%\unica-cursor"`
- Если папка есть и это клон этого репозитория: `git -C <папка> pull --ff-only`.
- Если папка есть, но это что-то другое, спроси пользователя, куда клонировать.

Не клонируй адаптер внутрь проекта пользователя.

## 2. Запуск скрипта

Скрипт запускается через Windows PowerShell 5.1 с обходом политики выполнения.

PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\unica-cursor\unica-cursor.ps1" <команда> [параметры]
```

bash (Git Bash):

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File "$USERPROFILE/unica-cursor/unica-cursor.ps1" <команда> [параметры]
```

Ниже это записано как `unica-cursor <команда>`.

## 3. Установи Unica

```text
unica-cursor install -Version stable
```

- По умолчанию устанавливай последнюю стабильную: `-Version stable` обходит
  интерактивное меню. Если пользователь попросил RC, уточни нужный тег
  (если он ещё не указан) и передай его через `-Version`, например
  `install -Version v0.15.0-rc.1`. Доступны RC, опубликованные после последней
  стабильной версии и новее неё. Для человека `install` без параметров
  показывает меню выбора.
- Не передавай `-Ref`, `-McpMode`, `-ExpandPaths`, `-Force`, если пользователь
  не просил их явно.
- Команда скачивает пакет, собирает его и загружает ядро со всеми движками
  закреплённых версий до активации. Это может занять несколько минут:
  дай ей время и не запускай повторно, пока она не завершится.
- При ошибке загрузки активная установка сохраняется. Устрани сетевую причину
  и повтори команду; повторная установка также восстанавливает кэш движков.
- Если установка остановилась из-за расхождения способа запуска Unica с эталоном,
  не добавляй `-Force` сам. Покажи различия пользователю и спроси.

## 4. Включи Unica в проекте

```text
unica-cursor enable -Path "<папка проекта>"
```

- Ядро и движки уже загружены при установке; построение индексов проекта
  при первых обращениях всё ещё может быть долгим.
- Если `enable` предупредил, что исходники 1С не найдены, передай это
  пользователю: проекту нужна выгрузка конфигурации в файлы. Включение при этом
  выполнено, `enable` можно повторить после выгрузки.
- Если `enable` сообщил о чужой записи сервера `unica` в `.cursor/mcp.json`,
  не добавляй `-Force` сам, а спроси пользователя.

## 5. Проверь результат

```text
unica-cursor status -Path "<папка проекта>"
```

Убедись, что есть активная установка, хук зарегистрирован, а в проекте есть
маркер `.cursor/unica.enabled`.

Если проект в Git, посоветуй пользователю закоммитить изменения `.gitignore`
(`git add -- .gitignore`): Unica читает `.gitignore` из индекса Git.

## 6. Попроси пользователя перезагрузить окно

Сам ты этого сделать не можешь. Скажи пользователю:

> Нажмите `Ctrl+Shift+P`, выполните **Developer: Reload Window** и откройте
> новый чат. Затем попросите агента вызвать `unica.view {}`. Он должен показать
> ваш проект и найденные наборы исходников.

До перезагрузки инструменты Unica в текущем чате недоступны. Это нормально.

## Чего не делать

- Не копируй навыки Unica в `%USERPROFILE%\.cursor\skills`, `.codex\skills`,
  `.claude\skills` и другие глобальные папки навыков. Тогда Unica загрузится во
  все проекты, и выборочное включение перестанет работать.
- Не правь вручную `%USERPROFILE%\.cursor\hooks.json`, `%USERPROFILE%\.cursor\unica`
  и `.cursor/mcp.json` проекта: этим управляет скрипт.
- Не создавай `v8project.local.yaml` и не спрашивай логин и пароль базы, если
  пользователь об этом не просил. Если просил, следуй разделу
  «Информационная база» в [usage.md](usage.md). Пароль не выводи в чат и не коммить.

## Если что-то пошло не так

- Журнал установки: `%USERPROFILE%\.cursor\unica\logs\install.log`.
- Почему Unica не включилась в окне: `%USERPROFILE%\.cursor\unica\logs\hook.log`.
- Откат на предыдущую версию: `unica-cursor rollback`.
- Отключить в проекте: `unica-cursor disable -Path "<папка проекта>"`.

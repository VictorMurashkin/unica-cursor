# Unica для Cursor: подробное руководство

Краткое описание и быстрый старт — в [README](../README.md).

Адаптер ставит [Unica](https://github.com/IngvarConsulting/unica) на компьютер один раз
и включает её только в тех проектах, где есть файл `.cursor/unica.enabled`.
В остальных проектах навыки и MCP-сервер не загружаются.

Форка нет. Скрипт скачивает готовый пакет из
[unica-marketplace](https://github.com/IngvarConsulting/unica-marketplace),
добавляет манифест Cursor, описание MCP-сервера и прослойку `unica-cursor-shim.exe`.
При каждом обновлении Unica эта адаптация повторяется.
## Требования

- Windows 10/11 x64.
- Windows PowerShell 5.1 (встроен; обёртка `unica-cursor.cmd` вызывает именно его).
- .NET Framework 4 x64: компилятор `csc.exe` из `Framework64\v4.0.30319` собирает прослойку.
- `git` в `PATH`.
- Cursor.
- Доступ к GitHub: `github.com` для клона пакета и загрузки ядра и движков Unica.
  Прокси — см. раздел «Первый запуск».
- Версия пакета Unica не ниже `0.13.0-rc.6`. Более старые версии скрипт отклоняет.
  Теги каталога с `v0.9.1` по `v0.13.0-rc.5` указывают на предыдущую версию пакета,
  поэтому их тоже нужно ставить веткой: `-Ref main` или `-Ref next`.

Codex, Claude Code, Node.js, Python и Java не нужны. Платформа 1С нужна только
для операций с информационной базой; требования Unica к ней описаны в
[документации Unica](https://github.com/IngvarConsulting/unica-marketplace/blob/main/plugins/unica/references/tooling/v8project.md).

## С чего начать

Команды ниже запускаются из корня этого репозитория. `unica-cursor.cmd` обходит
политику выполнения PowerShell. Тот же набор команд есть у `unica-cursor.ps1`.

### 1. Установить

```powershell
.\unica-cursor.cmd install
.\unica-cursor.cmd install -Ref next
.\unica-cursor.cmd install -Ref v0.13.0
```

Без `-Ref` берётся ветка `main`. `-Ref next` ставит кандидат в релизы.
`-Ref` принимает ветку, тег или коммит `unica-marketplace`.

Установка сама по себе ни один проект не включает.

### 2. Включить проект 1С

```powershell
.\unica-cursor.cmd enable -Path "D:\Projects\MyConfig"
```

`-Path` можно не указывать, если текущая папка и есть проект. Тогда вызывайте
скрипт по полному пути. Повторный `enable` безопасен: уже созданные
`v8project.yaml` и `v8project.local.yaml.example` не перезаписываются.

### 3. Перезагрузить окно Cursor

В палитре команд (Ctrl+Shift+P) выполните **Developer: Reload Window** и откройте
новый чат. Уже открытые чаты подхватывают навыки и правило со следующего диалога.
То же самое нужно после `update`, `rollback` и `disable`.

### 4. Проверить в чате

- `unica.view {}` показывает корень проекта, наборы исходников и подсказки `next`.
  Корень должен быть вашим проектом, а `workspaceRootOrigin` равен `clientRoots`.
- `unica.run {}` возвращает словарь операций.
- `unica.check {}` проверяет, готова ли рабочая область.

Если корень чужой, смотрите раздел «Несколько папок» и режим `project`.

Дальше агент работает с исходниками 1С через инструменты Unica. Подключение
информационной базы нужно только для операций с базой (`push`, `pull`, `make`,
`launch` и других).

## Команды

| Команда | Что делает |
| --- | --- |
| `install` | Скачивает пакет, собирает установку, регистрирует хук `workspaceOpen`. |
| `update` | То же, что `install`: новая версия кладётся рядом, затем становится текущей. |
| `rollback` | Меняет текущую и предыдущую установки местами. Повторный вызов возвращает обратно. |
| `enable` | Включает Unica в проекте и создаёт файлы из раздела ниже. |
| `disable` | Снимает включение: маркер, запись сервера в проекте и блок правила. |
| `status` | Показывает активную установку, хук и файлы проекта (`-Path`). |
| `uninstall` | Удаляет установку и хук с компьютера. Файлы проектов не трогает. |

`update` без `-Ref` снова берёт `main`, а не ту ветку, которая была установлена
раньше. Режим MCP и `-ExpandPaths` сохраняются, если эти параметры не указаны.
Повторная установка той же версии, коммита, режима и признака путей использует
уже собранный каталог.

Параметры:

| Параметр | Команды | Назначение |
| --- | --- | --- |
| `-Ref <ref>` | `install`, `update` | Ветка, тег или коммит. По умолчанию `main`. |
| `-McpMode roots` или `-McpMode project` | `install`, `update` | Способ передать Unica рабочую папку. По умолчанию `roots`; при `update` сохраняется текущий режим. |
| `-Prefetch` | `install`, `update` | Сразу скачать ядро и все движки. |
| `-ExpandPaths` | `install`, `update` | Подставить в описание сервера абсолютные пути вместо `${userHome}` и `${CURSOR_PLUGIN_ROOT}`. Если при `update` параметр не указан, остаётся значение текущей установки. Выключить подстановку: `-ExpandPaths:$false`. |
| `-Force` | `install`, `update`, `enable` | Продолжить, если способ запуска Unica разошёлся с эталоном. При `enable` заменить чужую запись сервера `unica` в `.cursor/mcp.json` проекта. В режиме `project` переключить установку без вопроса, даже если сервер сейчас запущен. |
| `-Path <папка>` | `enable`, `disable`, `status` | Проект. По умолчанию текущая папка. |
| `-NoWorkspaceConfig` | `enable` | Не создавать `v8project.yaml`, образец подключения базы и строку `/v8project.local.yaml` в `.gitignore`. |
| `-NoRule` | `enable` | Не создавать и не обновлять `.cursor/rules/unica.mdc`. |
| `-KeepCache` | `uninstall` | Оставить скачанные ядро, движки и состояние провайдеров. |

## Что появляется в проекте

`enable` создаёт:

| Файл | Что |
| --- | --- |
| `.cursor/unica.enabled` | Маркер включения. Хук проверяет только наличие файла. |
| `.cursor/mcp.json` | Запись сервера `unica`. Только режим `project`. Если файл уже есть, перед записью рядом пишется `.bak`. |
| `v8project.yaml` | Наборы исходников, которые предложила Unica. Существующий файл не меняется. |
| `v8project.local.yaml.example` | Образец подключения информационной базы. Существующий файл не меняется. |
| `.gitignore` | `/v8project.local.yaml` и служебные пути Unica. Точные уже существующие строки не дублируются. |
| `.cursor/rules/unica.mdc` | Правило для агента. Текст берётся из `templates/unica-rule.mdc`. |

В `.gitignore` всегда добавляются `.build/unica`, `**/.build/`, `ConfigDumpInfo.xml`
и `DumpFilesIndex.txt`. Строка `/v8project.local.yaml` добавляется вместе с
файлами рабочей области; `-NoWorkspaceConfig` её пропускает. Unica читает
`.gitignore` из индекса Git, поэтому после `enable` выполните `git add -- .gitignore`.

Пустой маркер, созданный вручную, тоже включает плагин. В режиме `project` этого
мало: сервер должен быть записан в `.cursor/mcp.json`, что делает `enable`.
Маркер можно не коммитить. `enable` сам в `.gitignore` его не добавляет.

`disable` удаляет маркер, свою запись сервера и блок правила между
`<!-- unica-cursor:begin -->` и `<!-- unica-cursor:end -->`. Запись `unica`,
которую создал не этот адаптер, не трогается. Файл правила
удаляется, если кроме блока в нём ничего не осталось. `v8project.yaml`,
`v8project.local.yaml`, образец и строки `.gitignore` остаются: это описание
проекта, а не включение адаптера.

## Режимы MCP

`-McpMode roots` (по умолчанию). Сервер описан в `mcp.json` установки.
Рабочую папку Unica узнаёт от Cursor через MCP Roots.

`-McpMode project`. Запасной вариант, если Cursor не передаёт roots.
`enable` записывает сервер в `.cursor/mcp.json` проекта и передаёт папку через
`CLAUDE_PROJECT_DIR=${workspaceFolder}`. Путь к установке идёт через junction
`%USERPROFILE%\.cursor\unica\current`. В режиме `roots` этого junction нет.

Смена режима: `update -McpMode project` (или `roots`), затем в каждом уже
включённом проекте `disable` и `enable`. В режиме `project` переключение
установки, пока `unica-bootstrap.exe` запущен, спрашивает подтверждение.
`-Force` отвечает «да». Если отказаться, новая установка уже собрана, но
текущей не становится.

## Прослойка для Cursor

Cursor запускает `<установка>\cursor\unica-cursor-shim.exe`, а не
`unica-bootstrap.exe` напрямую. Скрипт собирает прослойку из
`templates/cursor-shim.cs` при каждой новой установке. Она поправляет три
расхождения Cursor со спецификацией MCP:

- на `roots/list` Cursor отвечает путём Windows (`h:\Проект`), а Unica ждёт
  `file:///h:/...` и иначе отказывает с `Client root must be a local file URI`;
- после переподключения без `tools/list` Cursor вызывает инструмент под своим
  именем (`unica_view` вместо `unica.view`), и Unica отвечает
  `tool is not in the canonical v0.13 profile`;
- агенту Cursor показывает только `content`, а Unica может оставить его пустым
  и вернуть результат в `structuredContent`. В чате это выглядит как `(omitted)`.

Журнал обмена: переменная окружения сервера `UNICA_CURSOR_SHIM_LOG` с путём к файлу.

Та же прослойка в режиме `--setup` нужна команде `enable`: она вызывает
`unica.view {}` и забирает предлагаемый `v8project.yaml`.

## Рабочая область (`v8project.yaml`)

Если файла нет и не задан `-NoWorkspaceConfig`, `enable` запускает Unica в папке
проекта и записывает поле `setup` из ответа `unica.view {}`: формат выгрузки и
найденные наборы (конфигурация, расширения, внешние обработки). Своих правил
поиска у скрипта нет.

Если исходников 1С нет, Unica файл не предлагает. Скрипт пишет предупреждение;
`enable` можно повторить, когда выгрузка появится. Первый такой вызов скачивает
ядро Unica и может занять время.

## Информационная база (`v8project.local.yaml`)

Чтение, поиск, проверка и правка исходников работают без базы. Операции
`unica.run` с базой (`push`, `pull`, `make`, `launch`, `infobase.create` и другие)
берут подключение из `v8project.local.yaml` в корне проекта. Это настройки
конкретной машины, поэтому `enable` добавляет файл в `.gitignore`. Пароль в Git
и в чат попадать не должен.

Рядом лежит образец `v8project.local.yaml.example`:

1. Скопируйте его в `v8project.local.yaml`.
2. Раскомментируйте `infobases.origin`. У Unica одна база с именем `origin`.
   Файловая база: `connection: 'File=build/ib'` (если её нет, Unica создаст её
   операцией `infobase.create`). Серверная: `connection: 'Srvr="srv01";Ref="dev";'`.
3. Если в базе есть пользователи и не включена аутентификация ОС, заполните
   `user` и `password`.
4. Без блока `tools.platform` берётся самая новая установленная платформа.
   На платформе 8.5.4.1683 при базе с пользователями чтение расширений
   (`extensions.list`) падает: `ibcmd config export --file` отвечает
   «Идентификация пользователя не выполнена». Если установлена 8.5.4, в
   `v8project.local.yaml` закрепите семейство `8.3.27`, как в образце.
5. Не добавляйте в этот файл `execution_timeout` и `push.partialLoadThreshold`:
   Unica 0.13 отказывается работать с конфигурацией, где они есть.
6. Проверка в чате: `unica.view {}` показывает
   `"infobase": {"configured": true, "source": "v8project.local.yaml"}`.
   План без записи в базу: `unica.run` с `op` `extensions.list` и `dryRun: true`.

Наборы исходников и формат выгрузки задаются только в `v8project.yaml`.

## Правило для агента

Правило велит агенту работать с исходниками 1С через `unica_view`, `unica_search`,
`unica_apply`, `unica_check`, `unica_run` и остальные инструменты сервера `unica`,
а не правкой XML и BSL напрямую.

- Если файла нет, он создаётся из шаблона целиком, с `alwaysApply: true`.
- Если файл уже есть, `enable` вставляет блок между
  `<!-- unica-cursor:begin ... -->` и `<!-- unica-cursor:end -->`.
  Повторный запуск обновляет только этот блок. Свой текст пишите вне блока.
- Перед изменением существующего файла рядом сохраняется `.bak`.
- `-NoRule` отключает этот шаг. `disable` убирает блок.

## Несколько папок в workspace

Хук смотрит только первую папку. Unica работает с первым MCP root, поэтому
проект 1С должен быть первым. Маркер в остальных папках не включает Unica;
причина пишется в `hook.log`.

## Обновление и откат

```powershell
.\unica-cursor.cmd update
.\unica-cursor.cmd update -Ref v0.13.1
.\unica-cursor.cmd rollback
```

Каждая сборка лежит в своём каталоге и после установки не меняется. Запущенный
`unica-bootstrap.exe` поэтому не мешает обновлению: на Windows занятый exe
заменить нельзя. Хранятся текущая и предыдущая установки, остальные удаляются.
Занятый каталог остаётся до следующего запуска.

Новая версия начинает работать после **Developer: Reload Window** в каждом окне.

Перед сборкой скрипт сверяет `.mcp.json` пакета с `templates/upstream-mcp.json`
и проверяет, что `bootstrap/launch.sh` по-прежнему вызывает `run --plugin-root`.
Если способ запуска изменился, установка останавливается и показывает различия.
Тогда поправьте `templates/mcp.json` и `templates/project-mcp.json`, обновите
эталон и повторите команду. `-Force` ставит пакет, не дожидаясь этой правки.
Поле `startup_timeout_sec` на решение не влияет: Cursor его не использует.

В установке исходный `.mcp.json` переименован в `.mcp.json.upstream`, чтобы
Cursor не запустил второй, неадаптированный сервер. В режиме `roots` рабочее
описание сервера — файл `mcp.json` установки. В режиме `project` его нет:
сервер живёт в `.cursor/mcp.json` проекта.

## Удаление

```powershell
.\unica-cursor.cmd uninstall
.\unica-cursor.cmd uninstall -KeepCache
```

Удаляются хук, установки, клон репозитория пакетов и журналы. `-KeepCache`
оставляет `%USERPROFILE%\.cursor\unica\runtimes` и `provider-state`.
Каталоги, которые держит запущенный Cursor, скрипт не удаляет: закройте Cursor
и удалите их по списку из предупреждения.

Маркеры, записи сервера и правила в проектах остаются. Снимите их командой
`disable` до удаления или после, пока скрипт ещё на месте.

## Где что лежит

Пути ниже — в профиле пользователя (`%USERPROFILE%`).

| Путь | Что |
| --- | --- |
| `.cursor/hooks.json` | Запись `workspaceOpen`. Чужие хуки не удаляются. Перед записью создаётся `.bak`. |
| `.cursor/hooks/unica-workspace.ps1` | Скрипт хука. |
| `.cursor/unica/installs/<версия>-<commit>-<режим>-a<N>` | Одна установка. Суффикс `-abs` есть у сборок с `-ExpandPaths`. `<commit>` — семь символов, `<N>` — версия адаптера. |
| `.cursor/unica/active.json` | Имена текущей и предыдущей установок. |
| `.cursor/unica/current` | Junction на текущую установку. Только режим `project`. |
| `.cursor/unica/source` | Клон `unica-marketplace`. |
| `.cursor/unica/runtimes` | Кэш ядра и движков. |
| `.cursor/unica/provider-state` | Состояние провайдеров Unica. |
| `.cursor/unica/logs/hook.log` | Включён ли проект и почему. Журнал обрезается, когда превышает 200 КБ. |
| `.cursor/unica/logs/install.log` | Журнал установок, отката и уборки. |

Ошибка хука не ломает Cursor: он возвращает `{}`, Unica остаётся выключенной,
а текст ошибки попадает в `hook.log`.

`status` печатает активную установку, режим, наличие прослойки, регистрацию хука
и по выбранному проекту: маркер, запись `unica` в `.cursor/mcp.json`, три yaml-файла
и блок правила.

## Первый запуск

При первом старте сервера Unica скачивает ядро. Движки добираются по мере
надобности: индексация, анализатор и другие задачи. Первые вызовы могут быть
долгими. `-Prefetch` скачивает ядро и все движки заранее; если загрузка не
удалась, установка всё равно считается выполненной, а недостающее скачается
при использовании.

Прокси Unica берёт из `HTTPS_PROXY` или `ALL_PROXY` (только HTTP-прокси),
сертификаты — из хранилища Windows.

## Чего не делать

Не копируйте навыки Unica в `%USERPROFILE%\.cursor\skills`, `.codex\skills`,
`.claude\skills` и другие глобальные папки навыков. Cursor загрузит их во все
проекты, и выборочное включение перестанет работать.
